🎯 Player2Tracker - Implementation Plan (initial iteration)
This plan creates the first iteration of the Player2Tracker API implementing a minimal scope (Games + Platforms CRUD) using .NET 10, EF Core code-first with migrations, SQLite for storage, and JWT authentication with ASP.NET Core Identity prepared for later friend/private-data features.

Scope delivered by this plan

Add EF Core packages and configure SQLite DbContext in the Infrastructure project.
Create domain entities: Game, Platform (in Domain project).
Create Application layer DTOs and service interfaces (CRUD) for Games and Platforms.
Implement EF Core repositories/DbContext in Infrastructure referencing Domain types.
Wire up services and DbContext in Api Program.cs (dependency injection) and configure JWT + Identity for authentication.
Create Controllers in Api project for Games and Platforms (RESTful endpoints: GET list, GET by id, POST, PUT, DELETE).
Add EF Core migrations and an initial migration for SQLite.
Add minimal seed data for Platforms and sample Games.
Add Swagger and secure endpoints (authorize POST/PUT/DELETE) while keeping GET endpoints public for now.
Risks and notes

Identity with JWT requires users and password storage; this plan adds IdentityUser with EF Core stores and config for JWT but does not implement full UI or registration flow beyond basic endpoints; plan will include a simple register/login controller to obtain JWT tokens.
SQLite has limitations for concurrent writes; fine for single-user/local use but consider SQL Server/Postgres for production scale.
Friend features and trophies are left for later iterations; domain model should be designed to extend easily.

Create domain entities — Add Game and Platform classes in PlayerTwoTracker.Domain with minimal properties (Id, Name, PlatformId, Status enum).
Create Application DTOs and service interfaces — simple CRUD methods.
Implement DbContext — PlayerTwoTrackerDbContext in Infrastructure registering DbSet, DbSet, and Identity tables.
Register DI in Api Program.cs — add DbContext with SQLite connection string, add Identity, configure JWT authentication, register application services.
Implement Controllers — GamesController and PlatformsController with routes and authorize attributes (POST/PUT/DELETE require [Authorize]).
Add simple AuthController — register and login endpoints returning JWT tokens.
Create initial EF Core migration and update database (dotnet ef migrations add InitialCreate; dotnet ef database update).
Seed initial Platforms and optionally sample games during DB initialization.
Test endpoints locally, verify JWT auth flow, and inspect swagger UI.
Install EF tools if needed: dotnet tool install --global dotnet-ef
From solution folder: dotnet restore
Add packages (from each project folder) with dotnet add package or modify csproj.
Create migration: dotnet ef migrations add InitialCreate --project PlayerTwoTracker.Infrastructure --startup-project PlayerTwoTracker.Api --output-dir Data/Migrations
Apply migration: dotnet ef database update --project PlayerTwoTracker.Infrastructure --startup-project PlayerTwoTracker.Api
Run API: dotnet run --project PlayerTwoTracker.Api
